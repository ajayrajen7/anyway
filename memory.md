## Decision log (settled — with rationale)
- **Separate repo from `phayalman`, not a monorepo or shared code.** State-management philosophy is inverted (server-truth-recompute vs. local-truth-offline-first) and the backend language differs entirely (TS vs. Go) — sharing code would mean fighting one architecture or the other continuously. Only the process/doc conventions carried over.
- **No monorepo tooling for `app/` + `server/`.** Two npm/go projects side by side is sufficient at this size.
- **Go toolchain floats to whatever `modernc.org/sqlite` needs** (currently pins `go 1.25.0` in `go.mod` after `go mod tidy`); the sandbox auto-downloaded it via `GOTOOLCHAIN=auto` without issue.
- **Migrations live under `server/internal/db/migrations/`**, not a top-level `migrations/` — `go:embed` cannot reach outside its containing package directory, so the path in `architecture.md` §B3's prose is illustrative, not literal.

Nothing user-facing depends on this until M9, but it's worth knowing the outbox is already accumulating real entries in local testing.
- **Swaps/additions (M5) are session-local and never synced anywhere** — `sessionOverlay` has no outbox entry of its own. The *effect* of a swap/addition does reach the server correctly (each `logged_sets` row already carries the right `exercise_id`/`provenance`/`added_by`, and those go through the normal outbox path), but the overlay record itself — "this session, slot X became exercise Y" — is disposable, reconstructible, and was never meant to sync. Worth a second look only if some future feature needs to know "did a swap happen" independent of what got logged.
- **A swapped-in exercise's stepper always starts from its own prescribed load/reps** (M5) — there's no offline last-actual data for it to pre-fill from (that would need a network call this screen can't make), so `lastActual` is cleared on swap and `prefillFor` falls back to the *original* slot's prescribed sets/reps/load, even though the swapped exercise itself may have a real history. A reasonable, documented tradeoff, not an oversight.
- **The exercise-library offline cache (M5) has no staleness/versioning check** — `Today.tsx` just re-fetches and bulk-replaces it every time it loads successfully. Fine at ~90 rows; revisit only if the library grows enough for this to matter.
