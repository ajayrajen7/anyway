- **M3 ✅ Today + session creation.**
  - `server/internal/today/`: `Get(ctx, conn, date)` implements `GET /api/today`. Determines the active phase (latest `phases` row — see decision log), maps the date to a weekday, looks up that phase's day_template, and branches: non-lifting days (`cardio_mobility`/`rest`) return just the day_template info with `session: null` and `slots: []`; lifting days lazily create a `'planned'` session row on first view (`sessions.date` is UNIQUE, so repeat views return the same row, never a duplicate) and return it with its slots — each slot carrying its exercise, its tier-1 swaps, and a `last_actual` (most recent `status='done'` `logged_sets` row for that exercise, across any session — `'skipped'` sets never count, tested explicitly).
  - **"Missed days do not reschedule" (§A3.2) is structural, not a rule the code has to remember**: the day_template lookup is purely `(active phase, weekday)`, so there is no code path where Thursday's outcome could influence what Friday shows. The only "missed" handling anywhere is `sweepMissed`, run at the top of every `Get` call: any still-`'planned'` session dated before the requested date flips to `'missed'`. No cron/background job — a single-user PWA that's opened at least once a day doesn't need one, and one wasn't built. Tested directly: view Thursday, don't complete it, view Friday two days later — Friday shows its own full 7-slot template, and only *then* does re-viewing Thursday show it flipped to `'missed'`.
  - **Amendment to architecture.md §B5** (logged there too): `GET /api/today` takes an explicit `?date=` query param — the client's *local* calendar day, not the server's, since the server can't otherwise know the user's timezone. Falls back to the server's own local date only if omitted (manual/curl convenience). New frontend helper `src/lib/date.ts#localDateKey` builds this from local `Date` getters, deliberately not `toISOString()` (which is UTC and would misname the day near local midnight in a timezone ahead of UTC) — has its own unit tests including a late-evening case.
  - **Decision, not yet a problem**: "active phase" = the most-recently-seeded `phases` row (`ORDER BY id DESC LIMIT 1`). Fine while only Phase 1 exists. Once Phase 2/3 are seeded, or the Settings phase-switcher (§A3) is built, this needs a real "current phase" concept (a settings row, most likely) — flagged here so it's a deliberate decision when reached, not a silent breakage.
  - HTTP layer (`internal/api`): `GET /api/today` returns 400 for an unparseable date, 404 if no phase/day_template is seeded yet (never a lying 200), 200 otherwise. `TestApiRoutesRequireBearerToken`'s auth-gate check was moved off `/api/today` (now real) onto `/api/week` (still a stub) so it keeps testing "does auth gate the route" independent of any one route's actual behavior.

Mobility checkbox and the evening protein row are still explicit TODOs (M6/M7).

All green: `go vet`/`go test ./...`/`go build ./...` and `npm run typecheck`/`lint`/`test`/`build`.

## Decision log (settled — with rationale)
- **Separate repo from `phayalman`, not a monorepo or shared code.** State-management philosophy is inverted (server-truth-recompute vs. local-truth-offline-first) and the backend language differs entirely (TS vs. Go) — sharing code would mean fighting one architecture or the other continuously. Only the process/doc conventions carried over.
- **No monorepo tooling for `app/` + `server/`.** Two npm/go projects side by side is sufficient at this size.
- **Go toolchain floats to whatever `modernc.org/sqlite` needs** (currently pins `go 1.25.0` in `go.mod` after `go mod tidy`); the sandbox auto-downloaded it via `GOTOOLCHAIN=auto` without issue.
- **Migrations live under `server/internal/db/migrations/`**, not a top-level `migrations/` — `go:embed` cannot reach outside its containing package directory, so the path in `architecture.md` §B3's prose is illustrative, not literal.
