- **M3 ✅ Today + session creation.**
  - `server/internal/today/`: `Get(ctx, conn, date)` implements `GET /api/today`. Determines the active phase (latest `phases` row — see decision log), maps the date to a weekday, looks up that phase's day_template, and branches: non-lifting days (`cardio_mobility`/`rest`) return just the day_template info with `session: null` and `slots: []`; lifting days lazily create a `'planned'` session row on first view (`sessions.date` is UNIQUE, so repeat views return the same row, never a duplicate) and return it with its slots — each slot carrying its exercise, its tier-1 swaps, and a `last_actual` (most recent `status='done'` `logged_sets` row for that exercise, across any session — `'skipped'` sets never count, tested explicitly).

No cron/background job — a single-user PWA that's opened at least once a day doesn't need one, and one wasn't built. Tested directly: view Thursday, don't complete it, view Friday two days later — Friday shows its own full 7-slot template, and only *then* does re-viewing Thursday show it flipped to `'missed'`.
