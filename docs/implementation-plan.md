# Implementation Plan — Anyway

Build order per `architecture.md` §B7, expanded into milestones. **Steps 1–5 (M1–M5) are a usable product** — ship those before M6–M10.

TDD discipline (carried over, adapted): failing test first → make it pass → refactor. Intensity is *rigorous* on the coverage math (§B4 query, weekly aggregation), the offline outbox/sync logic, and the Vault lock; *lighter* on screen-level UI — state + flow tests, not exhaustive. `go test` for the backend, Vitest + Testing Library for the frontend, Playwright for the one true end-to-end path (session runner, offline).

## Milestones

- **M0 — Scaffold.** ✅ Vite+React+TS+Tailwind PWA frontend (route stubs for all 9 screens, Dexie schema shell, API client shell). Go+chi+SQLite backend (schema migration applied verbatim from §B3, bearer-token middleware, all `/api/*` routes stubbed 501 so the frontend can point at a live server immediately). CI (lint+typecheck+test+build, both sides). Docs + CLAUDE.md + memory.md.
- **M1 ✅ Exercise library.** `seed/exercises.json` (75 usable + 14 blocked, §A5.4/A5.3) + `server/internal/seed` (parse/validate/upsert) + `server/cmd/seed` CLI + `GET /api/exercises` (search, excludes blocked unless `?include_blocked=1`, but a blocked search hit still returns with its reason). See `memory.md` for the pool-sizing bug caught along the way.
- **M2 ✅ Phase 1 programme seed.** `seed/phase1.json` + `server/internal/programme` (parse/validate/apply) + `server/cmd/programme` CLI. 7 day templates, 26 slots, 49 swaps. Two noted modeling exceptions where the schema has no field for what the prose describes (a seconds-not-reps hold, an AMRAP slot with no fixed rep target) — see `memory.md`.
- **M3 ✅ Today + session creation.** `server/internal/today` + `GET /api/today?date=` (param added to §B5, see architecture.md amendment) + the Today screen (§A3.2) rendering all three day-kind states. Missed-day-doesn't-reschedule achieved structurally (day_template lookup never looks at other days' outcomes) rather than as a special case — see memory.md.
- **M4 ✅ Session runner (the core).** Offline-first: `SessionRunner.tsx` reads only from Dexie (`todayCache` + `loggedSets`), never the API. Set logging (tap ✓), pre-fill from `last_actual` falling back to prescribed, stepper edit-then-commit for weight/reps, swipe-left to skip a set, exercise-level Skip/Next, a passive non-blocking rest timer, and a real (not stub) session summary. **Zero `<input>` elements in the subtree — tested directly**, satisfying §B6.1 literally rather than by convention. See memory.md for the Dexie schema additions and a couple of small design calls (keyed remount over effect-reset, null-not-zero for a skipped set's reps).
- **M5 ✅ Swap + add flows.** Tier-1/tier-2 swap (§A3.4) and add-exercise with mandatory attribution (§A3.5), both as sheets nested under `/session/:id` via `<Outlet/>` so the runner never loses its place. Offline search over a newly-populated `exercises` Dexie cache; provenance (`swap_in_list`/`swap_off_list`/`added`) recorded correctly in all four cases. Amended §B6.1 (asked and confirmed) to scope the no-text-input rule to the set-logging screen itself, not these two sheets. See memory.md for the swap/add data model (`SessionOverlay` + `buildRunnerSlots`).
- **M6 🟡 Morning check + notification.** Full-screen check (§A3.1) ✅ — offline-first (Dexie + outbox), absence-not-default enforced structurally (no code path writes a row except a real tap), tested. **Notification delivery (07:00 fire, 11:00 re-notify, 23:59 cutoff) deliberately deferred** — asked and confirmed with the owner rather than assumed; real Web Push needs a server-side subscription store + scheduler + VAPID keys and real-device verification, none of which fit a sandboxed session. See memory.md open items for the scoped follow-up. Until it exists, `/check` is URL-only, not linked from navigation.
- **M7 ✅ Protein, mobility, cardio logging.** Protein Yes/No row (after 18:00, shown on every day kind) + a daily mobility checkbox on lifting days, both offline-first (Dexie + outbox). The Wed/Sat cardio_mobility day (§A3.6) is now real: cardio checkbox + duration stepper, "Full mobility" checkbox + expandable (unpersisted) checklist, Done in 3 taps. A cross-doc discrepancy (12 vs. "13" mobility items) found and flagged rather than papered over — see memory.md.
- **M8 ✅ Week view.** Computed entirely offline (see §B5's M8 amendment): a new `GET /api/programme` read endpoint (cached client-side, phase-wide/constant) supplies prescribed coverage; local `loggedSets`/`morningChecks` supply actual coverage and the pain strip. §B4's query reproduced as plain TypeScript over Dexie data in `src/lib/week.ts`. Single scroll view, no tabs (§B6.5), no chart beyond one week (§B6.6). Caught and fixed a real bug along the way: bucketing by a set's own `logged_at` (UTC) could misattribute it to the wrong local day/week — fixed by keying to the set's session's local date instead. See memory.md.
- **M9 ✅ Offline outbox + sync + the Vault.** `POST /api/sync` batch-drains the outbox built up since M4 (`logged_set`, `session_complete`, `morning_check`, `protein_log`, `mobility_log`, `cardio_log`, `weigh_in`), idempotent by `client_uuid` for `logged_set` and by natural key for everything else, one bad entry never failing the batch (`server/internal/sync`). Vault (§A4): a new `settings` table holds `programme_start_date` (set once, automatically, when the programme is seeded); `GET /api/weigh-ins` → 423 before `start+84d`, enforced server-side and defaulting to **locked** if no start date is recorded at all. Weigh-in (`/weigh`) built for the first time — Sunday-gated, blind-entry stepper. Two schema gaps closed (`settings`, `logged_sets.client_uuid`) that earlier milestones' docs already implied but never actually added. See `memory.md` for the full reasoning, including two routes left permanently 501 by design and `GET /api/week` staying an unbuilt stub for good.
- **M10 🟡 Export + nightly backup.** `GET /api/export` ✅ — full JSON dump, `weigh_ins` gated by the Vault like `GET /api/weigh-ins`. Nightly `VACUUM INTO` ✅ (`server/internal/backup`, with pruning) — but the **off-box copy** half of §B2's "the one unrecoverable failure mode" is not built: no destination was ever specified, and picking one (S3? another host? which credentials?) is a real infrastructure decision, not something to assume. `backup.OffBoxCopy` is the ready extension point. See `memory.md` for the open question this leaves for the project owner.
